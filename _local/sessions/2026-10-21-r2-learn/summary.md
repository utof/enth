# Summary: R2 Learn research (2026-10-21)

Three reports, written in parallel: [01 pedagogy and curriculum](01-pedagogy-curriculum.md), [02 content packs and delivery](02-content-packs.md), [03 architecture, risks and the lane plan](03-architecture-plan.md). The coordinator wrote this summary. The decisions below are provisional until the owner steers; work proceeds on them meanwhile.

## The answer

- **A lesson teaches one control or idea in 5–10 minutes:** Hear → Name → Try → Do → Check, then Review in later sessions. You hear a contrast (A/B pairs that change only the new control) *before* the explanation; the evidence favours that order over "explain, hear, do, check" (01 §1).
- **The curriculum follows the Recreate generator's order** (sources, filter, amp envelope, envelopes as modulators, LFOs, voices, effects, macros): 36 lessons in 9 units plus 6 sound-design studies built from the preset candidates. Together they cover all 54 parameters of the P1 modules. **A 12-lesson "tour"** (one per module, about 1.5 h) is GR2's friend track and is built first (01 §4).
- **Lessons reuse what exists:**
  - a lesson's "recreate this" step is a real Recreate round (A/B, rings, the 4-level coach, the results drawer);
  - the coach's levels are the hint ladder, with hints fading by tier;
  - "show me the closest passing patch" (CMA-ES from your own patch, a new `closest.rs`) follows a failed Submit, and after it, as after a Reveal, you must solve a sibling challenge (01 §3, §5; 03 §5).
- **"Deconstruct this preset" lessons are generated by ablation:** remove each element, measure what the sound loses, drop what's inaudible, then rebuild in signal-flow order with with/without A/B at each step. Factory studies get human-edited text; user presets get automatic lessons (01 §6; 03 §9).
- **Code home:**
  - a new core crate, **`enth-learn` (L5)**: the lesson and pack model, a pure lesson player, the checks, the deconstruct planner;
  - `enth-session::learn` (L6) binds it to the live patch and **enforces locks in the edit path**;
  - `enth-ui::editor::learn` (L7, feature `learn`) draws it;
  - the plugin, CLI and xtask do the I/O (03 §2).
- **Challenge v1 can't express a lesson,** so a **Challenge v2** (additive, with a v1 migration) is the one persisted change, and a judge agent reviews it at freeze F1l (03 §3).
- **Checks come in four kinds,** because sound alone can't check the compressor, reverb on held notes, resonance or macros (03 §4): patch state, sound expectations, Recreate scores and ear questions.
- **Delivery: bundle everything, no network code in R2** (02 §4, 03 §7):
  - about 60 lessons zip to about 0.2 MB, and a TLS stack would add 2.2 MB to an 11 MB plugin, so downloading doesn't keep the plugin light;
  - packs are `.enthpack` zips (a JSON manifest `enth.pack/1` with SHA-256 per file), embedded in the build, plus a `<Documents>/enth/Packs` folder for dropped packs and a "Get more lessons" button that opens the releases page in the browser.
- **Authoring loop first:**
  - `cargo xtask lesson-check` plays each lesson's reference solution through a real session, proves each check fails before it and passes after, checks reachability with the solver, and computes module coverage (GR2's mechanical half);
  - a `lessons.yml` workflow, since lesson-only commits run no CI today (02 §8, 03 §8–§9).
- **GR2 with a handful of friends** (01 §7):
  - parallel-form pre- and post-tests made of challenge codes;
  - a staggered mid-test, so each module family should improve only after its lesson;
  - "name up to three things you learned";
  - everything local, reported per person.

## Corrections to sub-reports

- **Markdown renderer.** 02 recommends `egui_commonmark` with a token adapter; 03 prefers a block AST through `LessonPane`. The coordinator takes 03's route: the lint already bans HTML, images and code blocks, so the subset is small; the token rule holds without an adapter; and the plugin doesn't take on a crate whose releases must track every egui bump. Revisit if lessons need tables or footnotes.
- **Challenge pieces.** 01 asks for a "lesson target" drawn per parameter; 03's v2 has only explicit patch targets. Both go into v2 (`Target::Draw` and `Target::Patch`), since a seeded draw gives siblings for redo and parallel test forms.
- **Delivery wording.** 02's "Packs folder + open folder" and 03's "Import pack…" are the same stage 1; the plugin offers both.
- **Review queue.** 03's lane plan has no lane for 01's Review (Leitner) queue; it is added as lane REV after LUI.
- **Pronouns.** Report 01 referred to the owner as "him" in two places; the owner is "they". The coordinator corrected those two words in the report, the only edit to it.
- **Placeholders.** 03 wrote before 01 and 02 were available; its curriculum size and pack format are superseded by 01 and 02.
